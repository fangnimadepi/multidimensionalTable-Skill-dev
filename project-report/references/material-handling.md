# 材料存放与解析

## 工作目录与配置

在 WorkBuddy 当前任务目录运行包内入口。入口优先使用 `JINGYAN_CONFIG` 指定的设置，默认读取个人目录下的 `鲸研配置.json`，首次按 [配置示例](workspace-config.example.json) 初始化。相对 `workspace_root` 以配置文件所在目录为起点。飞书连接器在任务目录下临时保存附件，再将核对后的材料存入个人工作区。

开始下载前一次性告知用户材料将保存的根路径。普通取材无需再次确认。默认单文件上限为 128 MiB，同项目选定材料合计上限为 192 MiB，均可配置。先查看远端附件大小，下载后再核对实际大小。超限时说明具体文件和大小，处理其他可独立执行的项目。用户可提高限制或提供压缩、拆分后的材料。

```text
鲸研工作区/
  <Base标识_表标识或local>/
    <记录标识或本地项目标识>/
      <本次运行标识>/
        raw/
          taskbook/        任务书原文件
          report/          阶段总结报告原文件
        extracted/         保留位置的文本、OCR和必要页面图像
        reports/           本次生成的报告
        run.json           配对、来源、读取范围与归档结果
```

用真实记录标识区分飞书项目，用运行标识区分不同次生成。本地项目没有记录标识时，用项目名和材料摘要区分。文件名只取原附件的末级名称，清除路径分隔符等平台不允许的字符，记录原名与保存名的对应关系。同名任务书和报告分别存放，符号链接和路径中的 `..` 不能使文件越出本次目录。原始材料保持原样，提取文本和生成文件使用各自子目录。运行记录保存材料角色、来源附件标识、原文件名、实际路径、大小和 SHA-256。凭据沿用连接器和模型设置。

下载命令应明确给出完整目标文件路径，并核对下载回执中的实际路径。如果连接器只能写入当前任务的暂存目录，先在该允许目录内下载，核实后移动到约定的 `raw` 位置并记录路径。不要把失败的目标路径当成已保存路径。默认不自动删除原件、中间文件或旧报告。用户要求清理时，按明确的项目和运行目录处理。

复用前核对项目、附件标识、大小和可用的版本信息，核验本地文件摘要与上次记录一致。远端附件版本无法确认时重新下载，不按同名或同大小直接复用。重试沿用该项目本次目录，已成功下载且仍匹配的材料保留。

## 选择已有解析能力

先查看已安装且可调用的文档工具以及现有运行环境。使用少量探测确认所需能力，避免在每份材料上重复检查。解析环境与业务出稿分开处理。

| 文件情况 | 首选处理 | 必须保留的信息 |
| --- | --- | --- |
| DOCX | 本地报告运行库读取正文与表格 | 文档顺序、表格栏目与行列、未读取的图片或对象位置 |
| 有文字层的 PDF 阶段报告 | 本地报告运行库按文件页序提取文字 | 页码、表头、脚注、必要的页面版式 |
| 扫描或混合 PDF 阶段报告 | 本地报告运行库对需要识别的页面调用已配置的 OCR | 实际读取页、缺失页、关键数字和图表位置 |
| 旧版 DOC | 用已有 Word 或 LibreOffice 转出本次目录内的 DOCX 副本 | 原文件、转换后的文本位置及转换损失 |

需要核查提取内容时用 [运行库的 `read` 命令](report-runtime.md#命令)。单独查看 DOCX 时也可使用包内的标准库工具。先把输入放入本次目录的 `raw` 下，再执行以下命令。

```bash
python3 scripts/read_docx.py --run-dir "本次项目目录" --input "raw/taskbook/任务书.docx" --role taskbook
```

输出在 `extracted/taskbook.json` 和 `extracted/taskbook.txt`。报告材料使用 `--role report`。JSON 保留正文段落、表格行列及合并标记，文本文件便于阅读。`text_extraction` 只表示脚本的文字提取结果。图片、图表、公式、修订和文本框等提示需要结合原文件查看，页眉页脚、脚注和批注等未读取部分也会列出，不能因命令成功就认定材料已读完整。DOCX 的逻辑位置不冒充 Word 页码。脚本返回码 0 表示提取到正文文字，3 表示未提取到文字，2 表示失败。失败后不能复用前一次提取结果冒充本次读取。

首次使用由 [初始化入口](report-runtime.md) 在个人目录准备独立环境，后续业务执行复用明确的解释器和 OCR 设置。工具不足时先检查初始化状态，说明具体失败步骤，保留材料和项目进度。

## 确认读取范围

先核对文件格式、实际大小和来源。扩展名与内容不符、下载不完整、加密或损坏时，说明具体原因。DOC 文件改后缀不能成为 DOCX。PDF 可打开、可渲染封面或能读出页数，并不代表正文已读取。

在运行记录中分开记下「已下载」「已提取文字」「报告所需范围已读取」。后一个状态需要实际确认以下内容。

- 任务书中的相关阶段要求、里程碑、指标和测评口径，以及用于解释项目价值的必要背景。
- 总结报告中的目标完成表、进展与代表成果、总结及下一步计划。图片、图表或跨页表格对判断有影响时要读取对应内容。
- 来源编号可回到具体段落、表格行列或 PDF 页码。关键数字、单位、否定词、状态和表头关系清楚。

可先定位相关章节，再读取需要的页。纯封面、目录和非关键插图未识别不必阻塞其他已充分读取的内容。缺少关键章节或无法读清指标表时，不把技术读取失败变成项目未开展、未完成或不达标。

## 失败处理与交付

同一下载按 `download_retries` 有限重试。运行库自动判断文字层和扫描页。解析失败时从诊断定位文件、页码或缺少的工具；有已确认的替代材料时按 `parse_fallbacks` 继续。确定缺少依赖、加密、无权限或文件损坏时，说明具体原因，不重复相同失败命令。

能够支持部分结论时，可保留有依据的草稿并说明未读取的章节及影响。关键范围仍无法读取时，该报告记录为「材料读取未完成」，给出补充可复制文字版本、解密副本或相关页面等具体办法。已有总结报告读不出来时，不能自行转成任务书版成果报告。缺页和技术失败不写成 PI 需要解释的履约问题。

批次继续处理其余独立项目，保留当前项目已经完成的步骤。未完成的报告不作为完整报告自动归档。用户明确要求存档部分草稿时，文件名和交付说明标清范围。
