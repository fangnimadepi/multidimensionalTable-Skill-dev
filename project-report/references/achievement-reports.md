# 成果报告写法

从项目经理人想了解的实际问题切入。用项目独有的矛盾、使用场景或工作链路命名小标题，例如「设备停下来时，维修人员先看什么」。围绕读者理解成果所需的技术细节写作。简版可以独立阅读，科普长版补充为什么难、怎么解决和怎么用。按材料密度决定篇幅，给出必要细节即可。

## 有任务书和可读的阶段总结报告

标题用「项目阶段成果与后续推进分析报告」。先列有依据的项目信息。可用紧凑的事实表或短段落说明问题、已形成的代表成果、核心增量、结果与对标、应用价值、阶段与归属，缺少可支持的项可略过。

1. **简版**。单独成章，拟一个有项目特点的小标题，交代已做成的代表成果、如何发挥作用、对谁有用。明确成果成熟度和适用条件。
2. **科普长版**。单独成章，从一个具体问题开场，按需解释瓶颈、关键工作如何衔接、阶段验证结果以及使用条件。技术概念可通俗解释，假设的使用情景要明确标成示意。对标只使用材料中已有对比，保留测试范围与基线。
3. **后续推进判断**。自然放在详述结尾。结合现有价值、验证范围和下一步条件，说明值得跟进的具体工作以及判断何时应更新。验证完成数量只代表覆盖范围，实际通过率、可靠性及适用性以测试结果和条件为准。首次试用只能说明所测场景的表现。
4. **横版展示卡片**。用独立横向页呈现价值标题、一至两项代表成果、工作如何串起来、对谁有用、当前范围和后续关注。复用同一事实底稿，全部卡片文字与正文一起核对。Word 中保留可编辑文字，已实现和未来方向分别标识。
5. **材料来源与重点定位**。按目标计划、代表成果、验证范围等少量主题列相关章节或 PDF 页码，通常三至五条即可。不列逐观点对应表，不反复摘录正文。完整材料、关键来源与核对记录留在本地底稿。总结报告支撑实际成果，任务书说明原目标和应用背景。

同时出具履约报告时，成果稿聚焦形成了什么能力、可能怎么用以及继续推进要看什么。避免复述履约对照表和完整问题清单。两份报告分别阅读也能理解，成果状态与口径一致。区分前期基础与阶段新增、测试与部署、建议报送与正式采纳。

## 仅有任务书

标题用「预期成果分析（任务书版）」。先列有依据的项目信息，再按以下顺序成文。

1. **目标成果提炼**。按拟交付物整理「预期成果」「计划交付与关键指标」表。保留任务书明列的指标、单位和必要条件。
2. **成果表达**。先用项目概述交代拟解决的问题和做法。接着给有具体小标题的简版，说明计划产出给谁用、有什么用。科普长版用少量小标题讲清问题、方案衔接与使用情景。
3. **后续验证**。用一两句话指出后续总结报告、测试结果或演示材料能核对的具体内容，以任务书规定为准。
4. **横版展示卡片**。使用已核对的计划成果、项目概述和预期用途，显著标明「任务书版 预期成果」。
5. **材料来源与重点定位**。按目标、方案与应用场景等少量主题列任务书章节或页码，不列逐观点长表。计划中的交付、效果和场景用「拟」「计划」「预期」等措辞。前期工作即使已完成，也不要写成本项目的阶段成果。
