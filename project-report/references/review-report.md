# 项目阶段履约审查报告

输入为项目任务书和同项目的阶段总结报告。关注约定与报告所述的出入，以双方原文和当前阶段为依据。

## 一、项目概况与审查口径

首页展示有依据的项目信息。用几句话介绍项目目标和当前阶段，列出两份材料及已明确的审查基准。

## 二、计划与实际进展

先简述本期计划，再用一段说明实际做到哪里。用精简的对照表呈现本期有对应内容的条目。

| 任务书要求 | 计划节点 | 总结报告所述 | 审查判断 |
| --- | --- | --- | --- |

找不到具体节点时留空。综合材料判定是否达到、部分完成或明确未完成。对象、交付规格、统计口径或测评条件不同，应明确写出差异。材料未说明的事项放到确认区。未来节点在对照表之外简述，用于理解剩余工作。

## 三、项目出入点与对接重点

只显示有内容的分类。每个事项选一个主类别。同一批次的数量未达且已过节点时，合为一项，在数量差异中交代时间。只有时间方面有独立问题时才另列。

| 类别 | 典型情形 |
| --- | --- |
| 进度与计划节点差异 | 明确属于本期的工作仍在推进。判断逾期还需可靠事实时间。 |
| 交付内容与技术规格差异 | 计划要交付的版本、对象或范围与实际验证不同。 |
| 数量与性能指标差异 | 同口径计划数量为 300 项，报告明确同批次已完成 123 项。 |
| 验收标准与测评口径差异 | 测试集、基线、单位或评价范围不符合计划口径。 |
| 报告表述不一致 | 同一交付物在不同章节被写为已完成和仍在推进，且材料未说明范围差异。 |

每项顺序为「任务书要求」「报告完成情况」「出入情况」。例如，任务书要求中期验证 32B 模型，报告说明仅完成 8B 模型验证并计划随后验证 32B，可写为验证规格尚有差异，保留两侧出处。若 32B 仅为终期目标，且阶段未到，则作为后续对照信息。单凭某段没写成果，不能判定项目组未做。无可单列的差异时写「本节暂无单列的出入事项」，有待确认问题时在下方呈现。

### 综合审查意见

用一至两段概括阶段进展和对照判断，选最有解释力的事实说明依据。验收口径已写明时，核对成果状态和认定方式。保留投稿、录用、发表及交底、提交申请、受理等不同状态。遇到不同来源说法冲突时保留冲突，不择取更强的版本。

### 与 PI 老师确认事项

用几段项目经理人可以直接发给 PI 老师的话术，每段说明一个具体工作对象与要确认的问题。例如「想和您确认一下，报告中的 8B 验证是否为过渡验证？计划要求的 32B 验证目前到哪一步？」按自然段呈现，省去编号和长计划标题。语气保持专业自然，保留已经审定的问题及子条件，不为凑沟通背景增写项目事实。考核适用范围由项目经理人确认时，另作简短提示。合并同一问题，省略空标题。技术读取问题在交付提示说明。

## 附页　材料来源与重点定位

按「任务书目标与计划」「代表成果与关键指标」「主要出入点」等少量主题列相关章节或 PDF 页码，通常三至五条即可，复杂项目按必要主题合并。不要列逐观点的「对应内容／原材料位置」表，不反复摘录正文。报告内冲突需保留双方所在章节。报告正文中的重要范围和限制不能只放在附页。

完整材料、关键引用绑定及核对记录保存在本机工作底稿；精简的是展示，不将来源核对改成可选。没有真实位置不编造页码或标题。
