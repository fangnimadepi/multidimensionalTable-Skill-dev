# 个人报告模型配置

项目经理人可以直接说「帮我配置鲸研报告模型，用 DeepSeek Flash」。先按 [独立运行与初始化](report-runtime.md) 完成首次环境准备，使用其返回的个人配置。用户指定平台和模型后，复用个人环境和设置。

## 取得密钥

优先让用户把密钥粘贴到本机的私有文本文件。可以按用户要求创建并打开该文件，例如用户工作目录下 `local/待导入密钥.txt`，文件只含密钥本身。在聊天中说明保存位置，保存后用配置工具读取，避免把文件内容输出到对话。密钥文件使用当前用户权限保护，沿用本机已提供的私有文件操作能力。

用户也可主动在对话里提供密钥并授权配置。说明密钥会留在这段对话中，不重复展示密钥，不将其写入 Skill、报告、飞书表或命令参数。可用可控的标准输入传给配置工具。聊天和工具历史由宿主管理，Skill 无法承诺从历史中删除已出现的密钥。

## 固定配置入口

通过运行入口调用配置工具。`$ENTRY` 为 `scripts/run.sh` 的实际路径，`$KEY_FILE` 为用户刚保存的纯密钥文件路径。Windows 对应使用 `scripts/run.ps1`。平台与模型名按用户选择填写。

```bash
sh "$ENTRY" configure --provider deepseek --model deepseek-flash --key-file "$KEY_FILE"
```

也支持 `--key-stdin` 或用户可操作的终端中的 `--key-prompt`。密钥须通过上述输入方式提供。脚本执行一次最小模型请求，验证成功后保存平台、模型与本地密钥文件路径，密钥保存在个人配置旁的 `local/jingyan-model.env`。失败保留原配置，反馈平台、模型及可操作的错误原因，输出不含密钥。

已支持的平台标识与模型选择由包内 `runtime/scripts/private_model_settings.py` 限定。模型名不受支持时说明限制，不擅自替换用户选定的模型。完成后运行入口的 `doctor`，回复「已配置平台、模型，连接验证通过」及用户需要知道的文件位置。

每位用户使用自己的配置和密钥文件。配置存在而凭据缺失时先处理个人配置。个人凭据只供本机模型请求使用，工作底稿、报告与发布包采用各自独立目录。
